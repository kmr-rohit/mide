Configuration

Plain TOML files. Save one and mide reloads it.

Where settings live

FileWhat it holds
~/.config/mide/config.tomlYour settings: fonts, terminal profiles, behavior. Always trusted.
<project>/.mide/config.tomlPer-project overrides. Terminal commands in it need trust.
~/.config/mide/layout.tomlTheme, panel sizes, terminal dock. mide writes this as you resize and dock.
~/.config/mide/recent.txtRecent folders, newest first.
~/.config/mide/trusted.txtFolders whose project config may run commands.

A project's file overrides yours for the same setting. A typo never stops mide: the bad file is skipped and you get a message.

To create a commented starting file, run "Preferences: Edit Global Config" or "Preferences: Edit Project Config" in the command palette.

config.toml

[editor]
font_family = "Monaco"      # any installed monospace font
font_size = 12

[workspace]
keep_open_on_switch = false # true: opening another folder keeps files and terminals

[terminal]
scrollback = 10000
font_family = "Menlo"       # optional; follows [editor] when omitted
font_size = 13              # optional

[[terminal.profile]]
name = "Claude"
command = "claude"
args = []
cwd = "."
env = { ANTHROPIC_MODEL = "claude-opus-5-5" }

[project]
open_terminals = ["Shell", "Claude"]

[editor]

KeyDefaultMeaning
font_familyMonacoFont for the editor, diffs and (by default) the terminal. If it is not installed you get a notice and Monaco, Menlo, SF Mono or Courier New is used.
font_size12Between 6 and 48. Line height scales with it.

[workspace]

KeyDefaultMeaning
restore_sessiontrueReopen last time's files and caret positions, and recover unsaved text after a crash.
language_serverstrueStart the language server for the file's language when one is installed, for errors and Go to Definition.
keep_open_on_switchfalseWhen you open another folder, keep the open files and terminal sessions instead of closing them.

[terminal]

KeyDefaultMeaning
scrollback10000Lines of history kept per session.
font_family, font_sizethe editor'sTerminal-only overrides.

[[terminal.profile]]

KeyMeaning
nameShown in the picker. The same name as a built-in profile replaces it.
commandWhat to run, through your login shell. Leave it out for a plain shell. Shell syntax such as a && b works.
argsList of arguments, quoted for you.
cwdWorking directory, relative to the project folder. Falls back to the project folder if it does not exist.
envExtra environment variables for the session.

[project]

KeyMeaning
open_terminalsProfile names to start when a folder opens. Only starts sessions if none are running, so switching folders never piles up duplicates.

Work and personal profiles

A profile is a set of environment variables that mide applies to everything it runs: git commands, and every terminal session. It is meant for switching between, say, a personal GitHub account and a work one without editing global files. Define them in ~/.config/mide/config.toml:

[workspace]
default_profile = "personal"

[profile.personal]
git_name = "Your Name"
git_email = "you@example.com"
git_ssh_key = "~/.ssh/id_ed25519_personal"
color = "#3b82f6"
folders = ["~/Personal"]

[profile.work]
git_name = "Your Name"
git_email = "you@company.example"
kubeconfig = "~/.kube/config-work"
color = "#e5484d"
folders = ["~/work"]
env = { AWS_PROFILE = "work", OCI_CLI_PROFILE = "WORK" }

Switch from the chip at the bottom right of the window, or with Profile: Switch… in the command palette. Opening a folder picks a profile by, in order: the folder's own profile = "work" under [project] in .mide/config.toml, the profile's folders list, the one you last chose for that folder, your default_profile, the one you used last. The git window shows who commits are made as.

  • Nothing global changes. mide does not run git config --global. Profiles are environment variables (GIT_AUTHOR_*, GIT_COMMITTER_*, GIT_SSH_COMMAND, KUBECONFIG and your own), so two windows can use different profiles at once.
  • Terminals follow. New sessions start with the profile. A shell sitting at its prompt is switched in place. A session that is running something (Claude, an editor, a build) cannot change its environment from outside, so it is marked ⚠ until you run Profile: Restart Stale Terminals.
  • Your rc files cannot undo it. In zsh the profile is applied after your .zshrc, so export OCI_CLI_PROFILE=... there does not win. Other shells get the variables at start-up only.
  • A profile only sets what it lists, and unsets what other profiles set. A project's own .mide/config.toml may only name one of your profiles; profiles defined there are ignored until the folder is trusted.

keymap.toml

Run Preferences: Edit Keybindings from the command palette to create ~/.config/mide/keymap.toml with a list of actions. Saving it reloads the bindings. Your entries win over the defaults.

[[bind]]
key = "cmd-k cmd-d"          # a chord: two keystrokes in a row
action = "editor::DuplicateLine"
context = "Editor"           # optional

[[bind]]
key = "cmd-e"
action = "none"              # frees a key

layout.toml

You rarely edit this by hand, but you can.

theme = "dark"            # "light" or "dark"
sidebar_width = 224.0
show_sidebar = true
terminal_dock = "bottom"  # "bottom", "left" or "right"
terminal_height = 300.0   # used when docked at the bottom
terminal_width = 480.0    # used when docked left or right
git_locations_width = 200.0
git_commits_width = 380.0

Out-of-range or unreadable values fall back to sensible ones.

Themes

Two app themes, light and dark, cover everything except the text editor. The terminal changes with the app. Switch with ⌥⌘T or "View: Light Theme" and "View: Dark Theme" in the command palette.

Editor colors come from a built-in dark theme. The code can also read Sublime Text .sublime-color-scheme files, but there is no setting that loads one yet.
